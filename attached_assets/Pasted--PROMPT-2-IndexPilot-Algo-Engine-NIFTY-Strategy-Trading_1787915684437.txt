# PROMPT 2 — IndexPilot Algo Engine, NIFTY Strategy & Trading Infrastructure

Continue from **PROMPT 1**.

The IndexPilot Algo Dashboard and authentication system are already implemented.

Now build the **actual algo-trading infrastructure** behind the dashboard.

Do NOT rebuild the frontend/authentication from scratch.

---


**15-minute**

# 4. INDICATORS

Use:

* EMA 9
* EMA 21
* VWAP
* RSI 14
* ATR 14
* Volume 20-period average

---

# 5. LONG SIGNAL

Generate a BUY candidate when all configured conditions pass:

1. EMA 9 > EMA 21
2. Price above VWAP
3. RSI confirms bullish momentum
4. Breakout/swing-high confirmation
5. Volume > configured average
6. ATR/volatility filter passes
7. Trading window is active
8. No daily risk limit has been reached
9. No existing position
10. Broker/system health is normal

---

# 6. SHORT SIGNAL

Generate a SELL candidate when:

1. EMA 9 < EMA 21
2. Price below VWAP
3. RSI confirms bearish momentum
4. Breakdown/swing-low confirmation
5. Volume > configured average
6. ATR/volatility filter passes
7. Trading window is active
8. No daily risk limit has been reached
9. No existing position
10. Broker/system health is normal

Do not generate trades using a single indicator.

---

# 7. ENTRY

Use confirmation-based entry:

**Trend + VWAP + Momentum + Breakout/Breakdown + Volume + Risk Approval**

Avoid low-quality trades during abnormal market conditions.

---

# 8. STOP LOSS

Calculate SL using:

* Recent swing level

OR

* ATR-based stop

Use configurable parameters.

---

# 9. TARGET

Default:

**1:2 Risk/Reward**

Example:

Entry = ₹100

SL = ₹95

Risk = ₹5

Target = ₹110

The system should calculate target automatically.

---

# 10. POSITION SIZING

Formula:

```text
Risk Amount = Account Equity × Risk %
```

Then:

```text
Quantity = Risk Amount / Stop Loss Distance
```

Round quantity according to valid broker/exchange lot-size rules.

Never allow quantity to exceed:

* Available margin
* Broker limits
* Exchange limits
* User risk limits
* Strategy exposure limits

---

# 11. RISK CONFIGURATION

Support:

* 0.5%
* 1%
* 2%
* 5%

5% should be marked as **High Risk**.

Example:

Capital = ₹1,00,000

Risk = 5%

Maximum risk amount = ₹5,000.

The system must prevent the user from accidentally exceeding their configured risk.

---

# 12. DAILY PROTECTION

Implement:

### Maximum trades

3 trades/day.

### Maximum consecutive losses

2.

### Maximum daily loss

2R.

Once reached:

```text
ALGO = STOPPED
```

No new trades should be allowed for that trading session.

---

# 13. TRADING WINDOW

Initial strategy window:

**09:30–11:30 IST**

Optional second window:

**13:30–14:45 IST**

No new positions outside configured trading windows.

Implement automatic end-of-day position handling according to the strategy configuration.

---

# 14. AUTOMATIC KILL SWITCH

Stop new trading automatically if:

* Daily loss limit reached
* Consecutive loss limit reached
* Market data disconnects
* Broker API disconnects
* Position mismatch occurs
* Duplicate order detected
* Excessive slippage
* Abnormal execution
* System health failure

Record the reason in:

`risk_events`

and

`activity_logs`
